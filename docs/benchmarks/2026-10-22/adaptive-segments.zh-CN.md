# 抖音小视频自适应单路 A/B（2026-10-22）

## 结论

本次候选只对抖音来源且文件大小不超过 32 MiB 的媒体下载，把分段计划收窄为单段；其余来源和大于 32 MiB 的抖音资源仍按调用方给定的连接上限执行。真实 CDN 对照支持这条窄策略：4 个抖音样本、每个 5 轮，候选相对原 Rvdown 8 路在 **20/20 配对轮次更快**；配对耗时比的中位数为 0.552，几何均值为 0.536。按每个样本各自的五轮中位数看，耗时分别下降约 58%、49%、40%、33%。

这只证明候选优于本仓原 8 路策略的这 4 个抖音样本。**它没有证明 Rvdown 已整体快于 aria2**：这四个样本的 aria2 五轮中位耗时均低于候选；候选也只在其中两个样本低于 httpx-fetch。32 MiB 是当前候选阈值，不是密集采样得出的普适物理拐点。

## 如何解释“单路”与测试边界

策略在媒体主文件 Range 规划中把连接上限设为 1，所以 32 MiB 以内抖音媒体走完整响应；这是 SDK 传输规划，不是每个时刻严格只有一个 TCP socket 的承诺。调用方给的连接数仍是上限，不会被策略提高。HLS 分片并发与此策略分开，低层固定策略构造器也保持原行为。

此轮测的是单视频纯传输：计时含进程启动、请求、接收和最终写盘；SHA-256 与 ffprobe 参考检查在计时外。不是 HLS/DASH 等价编排、可用视频交付、SDK 宿主总资源或 Windows 10/11 成品验收。共同字节转发器可能改变最高吞吐，数字是这台 macOS arm64 主机上的同轮对照，不代表所有地区、帐号、清晰度、网络或平台子域。

网络使用基准自有字节转发器；解析和上游连接显式绑定物理接口 `en0`，按域名固定公开 DNS 快照，保留原始 HTTP/HTTPS URL，不修改系统代理或 Clash 配置。测试只读下载媒体，不写业务后端。签名 URL、请求头值、业务 ID、原始媒体和源清单没有进入仓库；测试媒体已清理，原始逐条结果留在私有临时目录。

# 视频优先的性能与兼容测试计划

2026-10-22 确认：**Rust — 性能、小占用、高速、安全；Video — 视频下载的方便、易用、高速；Download — 保留通用下载兼容。** 通用速度继续优化，产品主对照以真实视频的成功和完整交付为先。这是目标，实际领先与否由相应场景证据决定。

## 测什么、按什么顺序

| 顺序 | 场景 | 回答的问题 | 证据边界 |
|---|---|---|---|
| 1 | 实际抖音 CDN 单个视频：小/普通/较大文件 | 与 aria2、httpx-fetch 比，完整成功率、耗时、资源占用如何 | 主对照；新鲜直链和必要头由获授权调用者在运行时提供 |
| 2 | 其它真实视频 CDN、HLS、DASH 双流 | 能否方便地交付可播放、轨道正确的视频，包含合并要多久 | 各工具提供等价外部编排，不能把只收到播放列表算成功 |
| 3 | 中断续传、慢传、候选回退、重定向、过期、坏文件 | 出问题后的交付成功率、恢复成本与错误是否清楚 | 真实自然故障与人为注入分开；资源变更时不能拼错字节 |
| 4 | Rust SDK/CLI：单任务和独立批量场景 | 接入、进度、取消、错误码、并发调度是否易用 | 同核心契约；编排步骤、依赖和额外网络字节也要记录 |
| 5 | 通用 HTTP 文件与公开样本、回环 | 通用兼容、持续吞吐、具体阶段的实现开销如何 | 辅助回归/诊断，不替代实际抖音 CDN 成绩 |

真实平台测试不要求把 URL 解析、业务服务或凭据放进本仓。测试输入使用独立私有运行环境；公开方法和统计即可，不为可复现而泄露签名 URL、请求头值或来源身份。当前公共脚本只支持各自声明的公开输入，**尚不是正式抖音三工具基准入口**。

## 正式单视频对照

冻结每轮样本类别、数量和清单摘要；先验证直链可用，再让各工具下载同一资源。每个样本/工具至少五次，轮换顺序、顺序执行，避免并行争抢出口；不静默重取不同清晰度/不同内容，也不因失败缩小分母。签名过期需整轮标明并按同一规则重取，保留原失败记录。样本不足则明确是诊断小样本，不能推广全平台。

对照 Rvdown、aria2 与 httpx-fetch，分三档：单连接、相同连接预算、各自默认；另列调优档，不从多个设置中只选赢家。记录实际 TCP 连接、Range 和 HTTP 协议，区分 H2 流与 TCP 连接；小文件可能不触发分段。工具/SDK 调用、URL、下载输出分别处理，不让程序启动方式或上游解析耗时混进单一工具。

基线必须给双方相同的有效直链和必要请求头。aria2 默认头、缺 Referer/自定义头作为单独消融，回答特定 CDN 的兼容条件，不能故意让对手缺头后宣布速度领先。HTTP 头与 TLS 指纹是两层；HTTP URL 无 TLS，不能用它推断指纹效果。保持原始授权 URL，协议切换用相应获授权的实验，不盲改签名链接。

同轮固定公开 CDN IP、相同物理出口，记录 DNS、协议、连接上限及实际路由。系统代理/TUN 存在时，仅清代理变量不足以证明直连；需绑定出口并核查进程连接。基准自有字节转发器的共同开销和协议支持范围必须说明；**代理不支持原始协议导致的零字节退出是工具链故障，不能写成 CDN 403**。不得为了基准擅改用户系统代理配置。

## 两种时间与成功标准

| 口径 | 计时包含 | 成功要求 |
|---|---|---|
| 纯传输 | 进程启动、探测、连接、下载、最终写盘；如另报内部传输时间应明确边界 | 计时外完整大小/摘要核对通过；所有工具统一额外处理开关 |
| 可用视频交付 | 必需的视频/音频下载、HLS/DASH 处理、外置 ffmpeg、验证与最终落盘 | 可播放，时长/轨道正确，必需音频存在，无截断、错误页或播放列表冒充媒体 |

成功速度只统计成功子集，同时展示成功/计划总数和每个失败原因；超时、403、损坏、未执行、工具链故障都不能算通过。不要用零字节快速失败表示高速度。统一外部截止时间并与 SDK 内部超时区分。中断恢复计入丢弃字节、重复传输和第二次握手，不能只报最后一段。

按大小、媒体协议、来源和系统分组，报告单视频耗时中位数/范围、首字节、正文吞吐、网络字节、重试/恢复、CPU 与峰值内存。小样本不宣称稳定 P95；总占用包含子进程/运行时，二进制体积与 ffmpeg 等依赖体积分列。便利性记录 SDK/CLI 接入步骤、等价外部编排量、进度语义和错误处理，并标注客观事实与主观判断。

## 先排查再优化

慢样本可复现后，分别比较 HEAD→GET / 首 GET 接正文、单/多连接、同指纹重连/换指纹、HTTP 协议、动态分段/慢尾回收。每次尽量只改变一个因素；没有证据时不修改生产默认。参考 Aria2 Next、Hydra 等实现也要核对源码、许可、成熟度和适用条件，作者的微基准或网络成绩不算 Rvdown 成绩。

安全与正确性不让位：Range/强验证器/资源身份、原子落盘、断点、目标互斥、永久文件系统错误不重试等保持原语义。更快交出坏文件不算优化。既有离线回归和跨系统验证仍保留。

## 报告与接手状态

每轮绑定源码提交及干净状态、实际程序 SHA256、工具/系统/ffmpeg 版本、样本清单摘要、完整计划分母、逐条结果、计时边界与网络路径证据。输入配置、原始日志和媒体不发布；只发布经过白名单和历史审查的数值/类别统计。失败现场排查前保留，排查后删除媒体，保留脱敏证据。
